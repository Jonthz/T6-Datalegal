## Production deployment notes

A `production` deployment now needs the following env vars or the app refuses to
boot:

- `ENVIRONMENT=production`
- `SECRET_KEY` — ≥32 chars; generate with `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
- `MFA_ENCRYPTION_KEY` — Fernet key; generate with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
- `CORS_ORIGINS` — comma-separated origin list (e.g. `https://app.example.com`).
- `DATABASE_URL` — points at the production PostgreSQL.
- Optional: `TRUSTED_PROXIES` (CIDRs for XFF), `AUTH_RATE_LIMIT`, `MFA_RATE_LIMIT`, `SHOW_DOCS`.

To create the schema on a clean DB:

```bash
DATABASE_URL=... alembic upgrade head
```

## Known risks / carry-forward

- **slowapi in-memory store**: single-process only. Multi-worker deploys need
  a Redis/memcache backend (slowapi supports `RATELIMIT_STORAGE_URI`). Tracked
  as Sprint 5 carry-forward item.
- **Fernet key rotation** is not yet implemented; a rotated key would orphan
  existing rows. Add MultiFernet wrapper before first key rotation.
- **PostgreSQL backup**: still PENDING manual `pg_dump`. Per-tenant `--schema`
  or row-level filtered dumps are out of scope here.
- **passlib + crypt deprecation**: a single DeprecationWarning emits at test
  start; will break under Python 3.13. Already a sprint-5 carry-forward
  (project_sprint5_todos).
- **fpdf2 `ln=True` warnings**: 33 deprecation warnings in `reports.py` —
  pre-existing, not in this sprint's scope.

# Session 6B — Frontend Foundation and Glassmorphism Design System

> Same branch (`sprint/06-hardening-ui-foundation`), follow-up to Session 6A.
> Goal: lay down a production-quality frontend foundation (route config, design
> system, AppShell, API wrappers, types, placeholders) so that Sprints 7-9 can
> build module pages without re-litigating layout, styling, or HTTP boilerplate.

## Objective

Replace the single-page demo UI with a multi-route compliance workspace:

1. Maintainable route config with role-aware gating.
2. Coherent glassmorphism design system under `frontend/src/components/ui`.
3. AppShell (`Sidebar`, `Topbar`, `Breadcrumbs`) replacing the legacy `Layout`.
4. Typed API wrappers for **every** backend module, regardless of which page
   ships in 6B vs. 7-9.
5. Real API-backed executive dashboard (`/reports/kpis`, `/reports/trends`,
   `/alerts`).
6. Functional Alerts page (mark read, delete).
7. Refreshed Login / MFA / User Management pages in the new visual system.
8. English-only `i18n/en.json` with strings for every nav entry and module.
9. Screen map and API integration matrix in `docs/frontend/`.

## Visual system contract (used by every page)

- Background: `bg-shell-gradient` (deep navy → indigo radial + linear).
- Glass panels: `.glass-surface` (dark) / `.glass-surface-light` (subtle), both
  Tailwind-componentised via `GlassCard` / `GlassPanel`.
- Typography: Inter system stack, `text-ink-50` primary, `text-ink-300`
  secondary, focus ring `ring-brand-400/70`.
- Status colors: `risk-low` (emerald), `risk-med` (amber), `risk-high` (rose),
  `risk-crit` (rose-700). Always paired with a text label (`<RiskBadge>` /
  `<StatusBadge>`), never color-only.
- All interactive components are keyboard accessible and use `aria-*` where
  appropriate (`Modal` traps Escape, `DataTable` declares `scope="col"`).

## Known risks / carry-forward

- **No live module pages besides Dashboard / Alerts / Users.** Every other
  route renders a `<ModulePlaceholder>` with the endpoint reference card.
  Acceptable because Session 6B is explicitly the foundation gate; Sprint 7-9
  fill them in.
- **JWT in `localStorage`.** Same as previous sprints; acceptable for MVP, but
  XSS surface is not zero. Move to httpOnly cookie when a public CSP is signed
  off.
- **Trend chart is hand-rolled SVG.** Good enough for one series. When Sprint 9
  needs multi-series + tooltips we should introduce `recharts` or equivalent
  rather than re-roll.
- **No request cancellation / caching.** Pages do their own `useEffect`
  fetches. Revisit if duplicate fetches become visible during normal use.
- **AppShell polls `/alerts/unread-count` every 60 s.** Multiplied by tenants
  in a future SSE-less scaling regime, this becomes noisy. Promote to a
  WebSocket / SSE channel when alerts grow beyond toy volume.
- **i18n is one big en.json.** Acceptable for MVP. If we ever ship Spanish UI
  we will split by module and lazy-load.
