UC002 
Name 
Configure organizational profile 
Created by 
Team 6 DataLegal 
Description 
Allows the Administrator or DPO to set up and update the company's 
legal identity, tax information, and designated data protection officers. 
Actors 
Administrator, DPO 
Extends 
None 
Preconditions 
1. The user must have administrative privileges. 
2. The organizational account (Tenant) must be active. 
Postconditions 
1. The company's legal metadata is updated globally. 
 
 
 

 
2. All generated legal documents will use the new profile information. 
Flow 
1. The user navigates to the "Organization Profile" settings. 
2. The system displays the current business details (Name, RUC, 
Address, Sector). 
3. The user modifies the required fields. 
4. The user designates or updates the official DPO for the organization. 
5. The system validates the tax ID (RUC) format and mandatory 
contact fields. 
6. The user saves the configuration. 
7. The system confirms the update and records the change in the audit 
log. 
Table 25: Use Case 2 Documentation 
 
Field 
Description 
ID 
UC003 
Name 
Manage system master catalogs 
Created by 
Team 6 DataLegal 
Description 
Allows the DPO or Administrator to define and maintain the core 
classification lists (Legal Bases, Data Types, Threats, and Controls) 
used across all modules to ensure standardized data entry. 
Actors 
DPO, Administrator 
Extends 
None 
 
 
 

 
Preconditions 
1. The Administrator must have authenticated access to the system. 
2. For bulk loads, a standardized file (CSV/JSON) must be prepared 
according to the system's methodology. 
Postconditions 
1. Master catalogs are updated and visible in all dropdown menus of 
the Data Registry and Risk modules. 
2. An entry is created in the immutable audit log recording the catalog 
change. 
Flow 
1. The user enters the "Configuration and Catalog Management" 
module. 
2. The system displays tabs for different catalogs: Legal Bases, Data 
Types, Threats, and Controls. 
3. The user selects the specific catalog to manage. 
4. The user adds, edits, or deactivates a value (e.g., adding "Biometric 
Data" to the Data Types catalog). 
5. The system validates that the change does not violate referential 
integrity. 
6. The user saves the changes, and the system applies versioning to 
maintain historical data consistency.
