Assign Classification of Confidentiality Levels 
Created by 
Team 6 DataLegal 
Description 
Allows the DPO to classify information assets and personal data 
categories according to established confidentiality levels, determining 
appropriate security controls and access restrictions based on 
sensitivity and impact. 
Actors 
DPO 
Extends 
Register Technical Metadata of Assets 
 
 
 

 
Preconditions 
1. The DPO must be authenticated with classification authority. 
2. Information assets or data categories must be registered in the 
system. 
3. Confidentiality classification framework must be defined with clear 
criteria: Public, Internal, Confidential, Restricted/Highly Confidential. 
Postconditions 
1. Asset or data category is assigned an appropriate confidentiality 
level. 
2. Classification determines access control policies and security 
measures. 
3. Classification impacts risk assessment calculations (higher 
confidentiality = higher potential impact). 
4. Classification decision is recorded in the audit log with justification. 
Flow 
1. DPO accesses the "Asset Classification" module and selects an 
asset or data category requiring classification. 
2. The system displays asset details including associated treatment 
activity and technical metadata. 
3. DPO clicks "Assign Confidentiality Level" and reviews the 
classification framework with decision criteria (Public, Internal, 
Confidential, Restricted). 
4. DPO evaluates the asset considering data types, potential impact of 
disclosure, regulatory requirements, and business criticality. 
5. DPO selects the appropriate confidentiality level and provides 
written justification for the classification. 
6. The system validates and applies the classification, automatically 
updating security controls.
